# nano 产品替换

以实物参考为产品事实来源，将正确产品还原到已有场景。方法是先在原图副本中完整遮挡旧产品，再按有序实物参考生成，保留场景和人物的接触关系。当前人类明确要求和宿主路由优先于应用默认值。

## 输入与输出

输入：可读取的场景原图、对应产品实物参考、需要替换的位置及款色；可选模型、输出数量、比例、输出目录。源文件缺失时先定位附件，仍不可读取才请求路径。没有实物证据的商品事实冲突需要澄清。

输出：源文件引用、区域文件、同像素尺寸涂黑底图、提示词、生成请求与任务 ID、全部生成原件、实际尺寸和哈希、逐图质量检查，以及多张结果的编号对比图。输出保存到用户指定目录或任务工作区中新建的唯一目录。

本应用 Skill 负责素材匹配、遮挡选择、提示词和商品验收。所属 npm 包 `@petercjl/nano-product-replacement` 提供确定性本地处理及安装更新；媒体能力负责认证、模型校验、生成提交、任务恢复及下载。安装本包不授权付费生图，也不修改全局路由。

## 执行准备

读取当前宿主对应的 [Codex 适配](adapters/codex.json) 或 [SealSeek 适配](adapters/sealseek.json)，核对 [能力合同](capabilities.json)。本地处理先运行 `nano-product-replacement doctor --json`，检查 `local_ready`。媒体依赖和登录状态单独报告。

生图按宿主当前规则选择工具。人类明确选择 SealSeek 时使用下述依赖合同；一般 Codex 生图请求遵循宿主自带生图工具规则。需要 Nano Banana Pro 且当前路由不能提供时，报告具体能力缺口，等待人类明确选择支持该模型的提供方；保留其模型意图。

SealSeek 分支：逻辑依赖名为 `sealseek-media`，由 `@petercjl/sealseek-media-cli` 分发。通过 `sealseek-media skill source --json` 解析规范来源，完整读取其当前 `SKILL.md`，相对资源从该目录解析。核验 CLI 当前版本、能力、实时模型和参数合同。要求其支持有序参考图、多张输出、2K、任务 ID 查询恢复、原件下载和 dry-run/submit。缺失时返回 `CAPABILITY_UNAVAILABLE`，使用该包公开安装流程修复后回到本节；不复制媒体服务集成或依赖 Skill。认证和生成恢复全程由该依赖处理，交接输出为原任务 ID 和已下载文件，再回到第 5 步。

## 主线

### 1. 查看并匹配素材

实际查看场景和实物参考，记录每个目标的位置、品类、颜色、数量和参考文件对应。原场景中的产品可能正是错误来源。只用本张场景所需的实物参考；颜色或结构以当次提供的证据为准。识别记录供核验使用，提示词以简洁的参考对应关系表达。

### 2. 完整涂黑旧产品

每张新图重新识别范围，绘制覆盖多边形和人物保护多边形。以不透明黑色遮住旧产品全部可见区域，包括轮廓外缘、毛边、细小露出部分。默认在产品选区外扩图像短边约 1.5%，长毛或不确定处可到 2%–3%，以实际检查为准。允许覆盖紧贴产品的一圈背景。已经画到轮廓外的选区可以减小额外扩张。

先外扩产品区域，再扣除贴合人物实际边界的保护区，保留脸、头发、手、衣服及其他商品。保护区默认不外扩，指缝和手臂间隙中的旧产品仍应遮住。默认羽化 0；显式柔边时旧产品像素应全部落在实黑区。

需要本地助手时读取 [本地处理合同](references/local-processing.md)，使用包 CLI 的 `blackout`。该步骤只做确定性像素处理，不调用生成服务。原件保留，输出为 `masked-base.png`，区域修改后另取新文件名。

**实际查看涂黑全图，并放大检查轮廓一圈和人物接触处。** 可辨认的旧产品原色细线、纹理、毛边都需要补涂重查；同时确认人物没有误涂。脚本成功不代表选区正确。用户已提供合格涂黑底图时直接复用，回到第 3 步。

### 3. 编写简洁提示词并校验

参考顺序：第 1 张是涂黑场景，后续是对应实物参考。编号与位置、款色的映射按本张图重写。参考图片承担产品结构、外观和身份事实，文字主要说明修复目标、对应关系、朝向及保留要求。示例：

> 第一张图片中的旧产品已用黑色遮住。请按后续实物参考修复对应产品：左侧对应图 2，前景对应图 3。所有可见产品结构、比例、组件位置、材质、颜色、文字、标识和连接关系遵循对应实物参考。保持原位置、朝向、人物接触遮挡、人物姿势、服装、背景、构图与光线。完整替换黑色区域，输出完整场景图。

对未指定的参数，本应用建议每张场景 4 张结果、2K、最接近输入宽高比的支持档位，保持画面比例。人类明确说“只生成一张结果”时输出 1 张；“先测试一张”指一张输入场景，仍按默认候选数量。

人类选择 SealSeek 后，应用默认目标为 `nano-banana-pro`（显示名以实时目录核对）；当前人类明确模型优先。读取 [SealSeek 调用交接](references/sealseek-handoff.md)，再依当前依赖 Skill 校验与 dry-run。涂黑底图是普通有序参考图片，不是独立 inpainting mask。仅压缩参考副本以满足实时上传限制，并保留必要视角和可辨识纹理。

### 4. 提交并跟踪同一任务

在已有生成授权范围内，校验通过后提交一次并立即保存 task ID。按媒体能力跟踪到终态。未知提交结果、认证中断和超时都查询或恢复同一任务。部分结果先交付已有文件；增加生成批次需要人类提出。默认画布归档沿用媒体能力合同，用户明确的画布或位置参数保持不变。

### 5. 检查和交付全部结果

核对真实终态、请求与实际数量、文件存在、哈希、实际尺寸。请求参数如 2K 或比例不代表服务严格返回对应像素值。按 [本地处理合同](references/local-processing.md) 的 `collect` 整理已下载文件，保留全部原件并生成带编号对比图。

实际查看每张结果：先检查产品种类、数量、颜色、材质纹理和全部可见结构，再检查朝向、手部接触、人物变化、残留黑块及额外物品。商品一致性和纹理准确是验收核心；技术完成与视觉合格分开报告。

逐张给完整原图可点击入口，多图时另附编号对比图，4 张采用 2×2。保留全部候选，简短指出差异及偏差；请求和实际数量不一致时如实报告。简述模型、实际尺寸、工具实际返回的费用和保存位置。记录区域、提示词和任务信息供后续恢复与复查。

## 分支与演进

- 缺输入：定位真实附件或请求缺失事实，回到第 1 步。
- 缺本地能力：运行 doctor，按所属包安装/更新流程修复，回到执行准备。
- 缺模型特性：返回 `FEATURE_UNSUPPORTED`，保留明确模型与参考语义，获得人类选择后回到第 3 步。
- 媒体失败：按当前媒体依赖的相同任务恢复合同处理，回到第 4 步；无法恢复则交付已有结果及准确错误。
- 输出目录已存在：保留旧内容，使用新目录，回到相关处理节点。
- 未实际查看图片：标注视觉验收未完成；文件校验不代替视觉证据。
- 重复出现的方法或工具缺口：记录失败证据，进入另行授权的维护；普通运行不改自身 Skill 或适配。
